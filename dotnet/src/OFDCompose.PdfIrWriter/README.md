# PdfIrWriter — WP0.7

`WriteAsync(canonicalIr, irDigest, resources, limits, cancellationToken)` accepts canonical Layout IR bytes and owned Render Worker subset/image bytes. It returns a PDF 1.7 byte array, SHA-256 and an object map, or diagnostics with both outputs null. It does not read paths/URLs, shape, choose fonts, subset, paginate, or invoke OFD or a PDF generator library.

## Representation

- Page tree, shared resources, Flate streams, classic xref and trailer. ID is the first 128 bits of the canonical IR SHA-256; date fields are omitted. Enumeration is deterministic. No signing, attachments, encryption or PDF/A claim.
- One page CTM converts µm to points and flips Y. Primitive coordinates retain their supplied precision. Text uses `position + offset`, without adding baseline again. Text matrices counter-flip glyph outlines. Vertical runs retain supplied positions and glyph selection using Identity-H; no second vertical shaping pass.
- TrueType uses Type0 / Identity-H → CIDFontType2, FontFile2 and an explicit CIDToGIDMap. Codes distinguish `(subset GID, Unicode substring, IR x advance / font size)`; `/W` carries that advance in 1000-unit glyph space. Every glyph has an absolute text matrix. PDF font names carry deterministic six-uppercase-letter subset tags, unique per canonical resource ordinal.
- CFF uses **CIDFontType0**, with the unchanged Worker OTF bytes in **FontFile3 /Subtype /OpenType**. CID-keyed CFF maps subset GID through its charset; ROS comes from its explicit strings. Non-CID CFF uses GID as CID. Conflicting text/width mappings allocate another font dictionary sharing the same embedded bytes and descriptor. Never use `CIDFontType0C` as a font dictionary subtype or label an OTF container as raw CFF.
- Descriptor bbox, units/em, ascender, descender, cap height, italic angle, fixed pitch and PostScript name come from SFNT tables. Older OS/2 without cap height uses hhea ascent; StemV is a documented estimate of 80 (SFNT provides no universal stem-width field).
- Paths preserve cubic curves, fill rule, stroke, dash/cap/join and opacity. State clip coordinates are transformed into page space before applying the object CTM; image-local clips keep their canonical coordinates. The final unit-image matrix multiplies pixel extents by 1000 because image linear coefficients remain mm/pixel while the page user space is µm. JPEG uses original DCT bytes. PNG uses BigGustave, Flate RGB and an optional grayscale SMask.
- Consecutive paint operations are grouped into Form XObjects by existing semantic container (`nodeId`, repeat instance, table cell, section). Without container semantics, whitespace-free text can use individual glyph Forms. No paint operation is reordered. Each Form has an identity Matrix (the PDF default), a page-sized BBox in the existing µm coordinate system, no transparency Group, and explicit font/image/graphics resources. Forms never invoke other Forms; resource dictionaries cannot recurse through Form calls.
- Object maps include both the page-stream invocation and the actual **decoded Form-stream byte ranges** for each primitive; an object can have multiple ranges. Tests resolve the final xref/streams and verify glyph/image coverage. Offsets never refer to compressed bytes.

## Text profile and exactness

ToUnicode comes from logical cluster ranges, not cmap lookup. One glyph may map to multiple Unicode scalars, including supplementary characters; the same glyph may map differently at different source positions. A multi-glyph cluster partitions its scalar sequence over the original glyph indices (one scalar per glyph, remaining scalars on the last glyph). The relation remains inside the original cluster. Original glyph IDs retain the full uint32 contract, including explicit maps from IDs above Int32.MaxValue to actual subset GIDs. Combining `q́` has separate q and zero-advance acute mappings.

The current lossless extraction profile requires nonoverlapping logical ranges forming the logical text partition, every nonempty cluster to have at least one glyph, and no more glyphs than logical Unicode scalars. A glyph mapping beginning with a character in the pinned JavaScript whitespace set and containing printable characters is also rejected: the pinned pdf.js high-level extractor classifies the entire mapping as whitespace and drops those printable characters. Space+`A` and NBSP+`A` reproduce the same loss; U+0085+`A` remains supported because U+0085 is outside that JavaScript set. Mappings classified by the pinned categorizer as invisible format marks are rejected even when they contain only format characters (including supplementary Cf scalars). Its nonspacing-mark alternative precedence is preserved; category checks operate on Unicode scalars. Whitespace glyph mappings that the pinned API normalizes to a different Unicode value (such as NBSP or LF) are diagnosed per object; structural paragraph/page breaks and source metadata are not rejected. This is a reader-profile restriction, not a PDF format limitation. Ambiguous overlapping/reordered mappings, excess glyphs, and nonempty glyphless text return `UNSUPPORTED_FEATURE`; no invisible replacement text or coarse whole-run mapping is inserted. Glyphless empty text is supported. CID CFF ROS using predefined standard-string SIDs is explicitly outside this profile. These are diagnosed writer boundaries, not changes to the canonical IR schema.

Semantic Form grouping removes the earlier synthesized column separators without changing glyphs, ToUnicode mappings or geometry. All 14 fixed positive PDFs now pass **literal whole-page `getTextContent` equality**, including multi-font paragraphs with real spaces, tables/repeated cells and the wide-spacing synthetic mapping cases. No allowlist, whitespace stripping or Unicode normalization is used. The independent `showText` Unicode and `/W` checks remain, as does PdfPig `Page.Text` equality.

PdfPig merges combining marks into the preceding Letter: the combined sample verifies exact text and base geometry; isolated-glyph tests verify both q and acute positions independently. This is not a one-Letter-per-glyph proof.

**Open acceptance decision:** real Worker input `o  f` produces IR logical/display text `o  f` and four correctly placed glyphs, but stock pdf.js returns `o f` even with `disableNormalization: true`. The original Unicode remains in ToUnicode and PdfPig. Consecutive ASCII spaces have not been rejected or altered to hide this mismatch; strict acceptance for that normal case is pending the user's decision. See [ADR-0004](../../../docs/decisions/ADR-0004-pdf-writer-reader-profile.md) and the archived reader probes.

## Resource limits

The shared internal validation sources are compiled separately into each writer, with no OFD assembly/API dependency in PDF. Existing canonical/hash/reference, SFNT/checksum/outline and image policy checks are preserved. JSON bytes/depth/tokens/string bytes, pages, objects, glyphs, path commands (including aggregate Form/shared-clip expansion), resource closure/bytes and decoded pixels are bounded. Conservative output reservation precedes decoding/emission; streams and final serialization also check output ceilings. PDF objects are capped at 100,000, font variants at 256 per subset and a ToUnicode destination at 512 bytes. PNG remains 8-bit noninterlaced, APNG rejected; JPEG remains 8-bit gray/RGB with EXIF orientation 1. Limits may only lower ceilings. Cancellation is propagated through JSON token scanning, canonical quoting/recursion, reference traversal, resource enumeration, SFNT checksums/outlines/CFF parsing, PNG CRC/inflate/pixel scans, JPEG scans/output blocks and decoder stream IO, and is checked during object/text/path/pixel/font emission, each compression chunk, object finalization and immediately before returning success; cancellation propagates as OperationCanceledException without a result. Cancellation is cooperative at owned loops and decoder IO boundaries; bounded third-party/BCL calls may finish before the next checkpoint.

Pinned pdf.js source evidence: `pdfjs-dist@5.4.149/legacy/build/pdf.worker.mjs` `getCharUnicodeCategory` uses `^(\\s)|(\\p{Mn})|(\\p{Cf})$`; its `category.isWhitespace` branch skips the entire mapped glyph string. The unchanged issue15 `logical-display` fixture maps one glyph to `\n<&`; high-level extraction loses `<&`. It is now an explicit negative test. A printable `XY` replacement fixture demonstrates ordinary logical/display differences still extract exactly. [Upstream category source](https://github.com/mozilla/pdf.js/blob/v5.4.149/src/core/unicode.js), [upstream extraction source](https://github.com/mozilla/pdf.js/blob/v5.4.149/src/core/evaluator.js).

RTL/nonmonotonic visual glyph arrays are encoded in explicit logical cluster order within the same text primitive. Original GIDs, positions, offsets, advances and cross-object paint order are unchanged; Unicode bindings are not swapped. Three RTL cases cover array reversal, right-to-left positions and same-color transparent overlap. Nonoverlapping references are pixel-identical. The overlap reference differs only at five measured edge pixels (15 channels, at most 1/255) in fixed Poppler; CI permits only that measured pixel set/count, not whole-page similarity. This is finite-precision same-color compositing, not permission to reorder different states/colors or different objects. Same-input PDF-byte determinism remains exact.

Encoding policy clarification: within a uniform-state text primitive, Tj traversal intentionally changes from the stored visual/shaping array order to logical cluster order. The input array/indices and cluster/GID/geometry association are retained; this is not a claim that per-glyph paint order is unchanged. The model attaches one color/alpha/clip/state to the text object. The measured same-color raster rounding bound does not authorize reordering objects or future per-glyph colors/blend states; such capabilities or out-of-bound examples require re-evaluation.

Semantics-free whitespace-bearing objects default to object-specific Forms. Only explicit leading/trailing whitespace glyph mappings connect adjacent text contexts, so a real boundary space is not dropped and unrelated columns do not manufacture a separator. Such connected groups are not split into glyph Forms; geometry never determines whether text is joined.

Page width and height are limited to 5,080,000 µm (14,400 default PDF user units). Larger canonical pages return `UNSUPPORTED_FEATURE` at the page ID; this writer does not apply `/UserUnit` scaling.

当前 untagged PDF profile 只支持实际非空 text 对象的 semantic readingOrder 与固定 page/paint 次序一致的输入；比较相对顺序，不要求 readingOrder 等于 drawOrder，忽略非文本及空 text 的顺序变化。冲突在分配输出前以对象 ID 的 `UNSUPPORTED_FEATURE` 诊断。该输入仍是合法 Layout IR；PDF 格式可表达结构阅读顺序，后续 tagged profile/readout adapter 需要独立实现与验证。原同一 text 内 RTL logical cluster 支持保留。

反序语义 BA / 绘制 AB 的真实 probe 已验证当前输出的 PdfPig 与 stock pdf.js 都提取 AB。固定 pdf.js 的 GetTextContent 调用 extractTextContent、PdfPig ContentStreamProcessor 按内容操作积累 Letter 的源码支持该提取路径判断；本次未构造和执行 tagged StructureTree 变体，不把源码检查冒充 tagged-reader 运行证明。普通双 ASCII 空格的用户验收项保持开放。
